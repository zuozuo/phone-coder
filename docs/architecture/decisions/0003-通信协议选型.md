# ADR-0003: 通信协议选型

## 状态

已采纳 | 2025-12-30

## 背景

Phone Coder 需要实现手机端与本地 Go Server 之间的实时通信，主要需求：

- 实时推送 Claude Code 输出（流式输出）
- 延迟要求低（< 500ms）
- 支持双向通信（发送消息 + 接收输出）
- 通过 Cloudflare Tunnel 穿透到公网

约束条件：
- 网络环境可能不稳定（移动网络）
- 需要支持断线重连
- 消息顺序需要保证

## 决策

采用 **WebSocket** 作为客户端与服务端的通信协议。

## 备选方案

| 方案 | 优点 | 缺点 |
|------|------|------|
| **WebSocket** | 真正双向通信<br>低延迟<br>浏览器原生支持<br>成熟稳定 | 需要维护长连接<br>断线重连需自己实现 |
| **HTTP Long Polling** | 实现简单<br>兼容性最好<br>穿透防火墙容易 | 延迟高<br>资源浪费<br>不是真正双向 |
| **Server-Sent Events (SSE)** | 实现简单<br>自动重连<br>HTTP 兼容 | 单向通信<br>需要额外 HTTP 请求发送消息 |
| **gRPC Streaming** | 高性能<br>强类型<br>双向流 | 浏览器支持有限<br>需要 gRPC-Web<br>配置复杂 |

## 决策理由

1. **真正双向通信**：WebSocket 支持服务端主动推送，无需客户端轮询
2. **低延迟**：建立连接后，消息传输延迟极低，满足 < 500ms 要求
3. **流式输出友好**：Claude Code 的输出是流式的，WebSocket 可以实时推送每个字符
4. **Cloudflare Tunnel 支持**：Cloudflare Tunnel 完整支持 WebSocket
5. **生态成熟**：
   - 浏览器/移动端：原生 WebSocket API
   - Go 服务端：gorilla/websocket 库成熟稳定
6. **简单协议设计**：JSON 消息 + type 字段区分消息类型，简单直观

## 消息协议设计

### 消息格式

```json
{
  "type": "message.stream",
  "sessionId": "sess_123",
  "content": "输出内容"
}
```

### 消息类型

| 方向 | 类型 | 说明 |
|------|------|------|
| C→S | auth | 密码认证 |
| C→S | session.list | 获取会话列表 |
| C→S | session.create | 创建会话 |
| C→S | session.delete | 删除会话 |
| C→S | message.send | 发送消息 |
| C→S | session.stop | 停止任务 |
| S→C | auth.result | 认证结果 |
| S→C | session.list | 会话列表 |
| S→C | message.stream | 流式输出 |
| S→C | message.done | 输出完成 |
| S→C | message.error | 错误消息 |

## 影响

### 正面影响

- 实时性好，用户体验佳
- 协议简单，易于调试
- 客户端和服务端实现都很直接

### 负面影响

- 需要自己实现断线重连逻辑
- 需要实现心跳保活机制
- 移动端网络切换时可能断连

### 需要的行动

- [ ] 实现 WebSocket 心跳保活（Ping/Pong）
- [ ] 实现客户端断线重连（指数退避）
- [ ] 定义完整的消息协议
- [ ] 实现消息序列化/反序列化
