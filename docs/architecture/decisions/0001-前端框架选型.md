# ADR-0001: 前端框架选型

## 状态

已采纳 | 2025-12-30

## 背景

Phone Coder 需要开发一款移动端 App，支持 iOS 和 Android 双平台。需要选择合适的前端技术栈来实现：

- 跨平台移动端应用
- 实时 WebSocket 通信
- Markdown 渲染和代码高亮
- 良好的移动端用户体验

约束条件：
- 个人开发者，需要高效的开发体验
- 需要尽快发布 MVP 版本
- 后续可能扩展 Web 端

## 决策

采用 **Ionic + React + Capacitor** 作为前端技术栈。

## 备选方案

| 方案 | 优点 | 缺点 |
|------|------|------|
| **Ionic + React + Capacitor** | 跨平台（iOS/Android/Web）<br>React 生态丰富<br>开发效率高<br>原生插件支持 | 性能略低于原生<br>复杂动画体验一般 |
| **React Native** | 接近原生性能<br>React 生态<br>热更新 | 需要原生开发知识<br>第三方库质量参差不齐<br>调试复杂 |
| **Flutter** | 高性能<br>UI 一致性好<br>热重载 | Dart 语言学习成本<br>包体积较大<br>生态相对较小 |
| **SwiftUI + Kotlin** | 最佳性能<br>平台特性支持完整 | 需要维护两套代码<br>开发成本翻倍<br>不适合个人开发者 |

## 决策理由

1. **跨平台能力**：Ionic + Capacitor 一套代码可以生成 iOS、Android 和 Web 应用，适合个人开发者
2. **React 生态**：可以复用大量 React 组件和库（如 Markdown 渲染、状态管理）
3. **开发效率**：Web 技术栈，开发调试效率高，热重载支持
4. **原生能力**：Capacitor 提供完整的原生 API 访问（存储、键盘、状态栏等）
5. **渐进式复杂度**：可以从 Web App 开始，逐步添加原生功能
6. **熟悉度**：团队/个人已有 React 开发经验

## 影响

### 正面影响

- 一套代码覆盖 iOS、Android、Web
- 开发效率高，迭代快
- 可以复用 Web 生态的组件库

### 负面影响

- 复杂动画和手势的性能不如原生
- 需要注意移动端性能优化（虚拟列表、懒加载等）

### 需要的行动

- [ ] 初始化 Ionic + React 项目
- [ ] 配置 Capacitor 原生插件
- [ ] 选择并配置状态管理方案（Zustand）
- [ ] 配置 Markdown 渲染和代码高亮
