# ADR-0002: 后端语言选型

## 状态

已采纳 | 2025-12-30

## 背景

Phone Coder 后端需要实现：

- WebSocket 服务，处理实时消息
- 管理 Claude Code 子进程（stdin/stdout 交互）
- 会话持久化（SQLite）
- 运行在本地 Mac 上，通过 Cloudflare Tunnel 暴露

约束条件：
- 需要高效的并发处理能力（WebSocket + 进程管理）
- 部署简单，最好单二进制
- 资源占用低（运行在开发机上）

## 决策

采用 **Go** 作为后端开发语言。

## 备选方案

| 方案 | 优点 | 缺点 |
|------|------|------|
| **Go** | 编译为单二进制<br>原生并发支持（goroutine）<br>内存占用低<br>启动快 | 泛型支持较新<br>错误处理繁琐 |
| **Node.js** | 开发效率高<br>npm 生态丰富<br>与前端技术栈统一 | 单线程模型<br>需要 node_modules<br>内存占用较高 |
| **Python (FastAPI)** | 开发效率高<br>代码简洁<br>自动生成文档 | 性能一般<br>需要运行时环境<br>并发处理复杂 |
| **Rust** | 极致性能<br>内存安全<br>单二进制 | 学习曲线陡峭<br>开发效率较低<br>编译时间长 |

## 决策理由

1. **单二进制部署**：Go 编译后是单个可执行文件，部署极其简单，无需安装运行时
2. **原生并发**：goroutine 天然适合 WebSocket 和进程管理的并发场景
3. **低资源占用**：Go 程序内存占用低，适合在开发机后台运行
4. **启动速度快**：毫秒级启动，适合服务重启
5. **标准库强大**：标准库提供 HTTP、WebSocket、JSON 等完整支持
6. **跨平台编译**：可以轻松为不同平台编译（未来支持 Linux/Windows 开发机）

## 影响

### 正面影响

- 部署只需复制单个可执行文件
- 并发处理简单高效
- 资源占用低，不影响开发机日常使用

### 负面影响

- 错误处理代码较多（Go 的 if err != nil 模式）
- 泛型使用相对不便

### 需要的行动

- [ ] 初始化 Go 项目结构
- [ ] 选择 WebSocket 库（gorilla/websocket）
- [ ] 选择 ORM（GORM）
- [ ] 配置项目构建脚本
