## 1. 功能概述

### 1.1 背景

Claude Code 执行某些任务可能需要较长时间，或者用户发现 AI 走错了方向，需要能够远程中断当前正在执行的任务。这可以节省时间和 token 消耗，避免错误操作造成更大影响。

### 1.2 目标

提供一键停止当前任务的能力，相当于在终端按 Ctrl+C。

### 1.3 范围

**包含**：
- 停止当前运行中的任务
- 停止状态反馈
- 停止失败处理

**不包含**：
- 部分停止（只停止某个子任务）
- 暂停/恢复功能
- 回滚已执行的操作

### 3.4 关键交互说明

**交互点1**：停止任务
- 触发方式：点击停止按钮
- 反馈形式：按钮变为"停止中..."，禁用点击
- 特殊说明：停止完成后按钮隐藏，状态变为 idle

**交互点2**：停止完成
- 触发方式：收到 Server 的 session.stopped 消息
- 反馈形式：在消息列表显示"任务已停止"提示
- 特殊说明：恢复输入框可用状态

## 4. 详细设计

### 4.1 业务规则

| 规则 | 说明 |
|------|------|
| 按钮可见性 | 仅在 status = running 时显示停止按钮 |
| 防重复点击 | 发送停止请求后禁用按钮，防止重复发送 |
| 停止机制 | 服务端向 Claude Code 进程发送 SIGINT 信号 |
| 停止后状态 | 会话变为 idle，可继续发送新消息 |
| 超时处理 | 如果 5s 内未收到停止确认，显示错误并允许重试 |
| 强制停止 | 如果 SIGINT 无效，发送 SIGKILL 强制终止 |

### 4.2 接口描述

#### 接口1：session.stop（客户端 → Server）

**功能说明**：停止当前运行的任务

**请求格式**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| type | String | 是 | 固定为 "session.stop" |
| sessionId | String | 是 | 会话 ID |

**示例**：
```json
{
  "type": "session.stop",
  "sessionId": "sess_123"
}
```

#### 接口2：session.stopped（Server → 客户端）

**功能说明**：通知客户端任务已停止

**响应格式**：

| 字段 | 类型 | 说明 |
|------|------|------|
| type | String | 固定为 "session.stopped" |
| sessionId | String | 会话 ID |
| status | String | 新状态，固定为 "idle" |

**示例**：
```json
{
  "type": "session.stopped",
  "sessionId": "sess_123",
  "status": "idle"
}
```

#### 接口3：session.stop.error（Server → 客户端）

**功能说明**：停止任务失败

**响应格式**：

| 字段 | 类型 | 说明 |
|------|------|------|
| type | String | 固定为 "session.stop.error" |
| sessionId | String | 会话 ID |
| code | String | 错误码 |
| message | String | 错误描述 |

**错误码定义**：

| 错误码 | 说明 | 用户提示 |
|--------|------|----------|
| SESSION_NOT_FOUND | 会话不存在 | "会话不存在" |
| NOT_RUNNING | 任务未在运行 | "当前没有运行中的任务" |
| STOP_FAILED | 停止失败 | "停止失败，请重试" |

### 4.3 状态流转

**停止操作状态**：

| 状态值 | 状态名称 | 说明 |
|--------|----------|------|
| idle | 空闲 | 按钮隐藏 |
| running | 运行中 | 按钮可点击 |
| stopping | 停止中 | 按钮禁用，显示"停止中" |

**状态流转图**：

```
+------------+   点击停止   +------------+   收到 stopped   +------------+
|  running   | -----------> |  stopping  | ---------------> |    idle    |
+------------+              +------------+                  +------------+
                                  |
                                  | 超时/收到 error
                                  v
                            +------------+   点击重试   +------------+
                            |   error    | -----------> |  stopping  |
                            +------------+              +------------+
```

### 4.4 服务端实现要点

```
收到 session.stop 请求
        |
        v
+------------------+
| 向 Claude Code   |
| 进程发送 SIGINT  |
+------------------+
        |
        | 等待 3s
        v
+------------------+     是      +------------------+
| 进程已退出？     | ----------> | 发送 session.stopped |
+------------------+             +------------------+
        | 否
        v
+------------------+
| 发送 SIGKILL     |
| 强制终止         |
+------------------+
        |
        v
+------------------+
| 发送 session.stopped |
+------------------+
```

## 5. 验收标准

| 场景 | 前置条件 | 操作步骤 | 预期结果 |
|------|----------|----------|----------|
| 正常停止 | 任务运行中 | 1. 点击停止按钮 | 2s 内任务中断，状态变为 idle，显示"任务已停止" |
| 无任务运行 | 状态为 idle | 1. 观察页面 | 停止按钮不显示 |
| 停止中状态 | 已点击停止 | 1. 观察按钮 | 按钮显示"停止中"，不可点击 |
| 停止失败 | 进程无响应 | 1. 点击停止 2. 等待超时 | 显示错误提示，提供重试按钮 |
| 强制停止 | SIGINT 无效 | 1. 点击停止 | 系统自动发送 SIGKILL 强制终止 |

### 6.2 风险评估

| 风险描述 | 概率 | 影响 | 缓解措施 |
|----------|------|------|----------|
| 进程无法正常停止 | 低 | 中 | 超时后发送 SIGKILL 强制终止 |
| SIGKILL 也无效 | 极低 | 高 | 记录日志，提示用户手动处理 |
| 停止后状态不一致 | 低 | 中 | 停止后主动刷新会话状态 |
